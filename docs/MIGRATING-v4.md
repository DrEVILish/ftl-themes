# Migrating from v3 to v4

> **BREAKING — v4.0.0 removes the `ftl-` prefix everywhere, with no compatibility layer.**
> Every class name, custom property, keyframe name and element id that started
> with `ftl-` is renamed. A v3 stylesheet reference or template that is not
> migrated will render **unstyled** against v4 bundles. The last v3 release is
> the `v3` branch (v3.14.0); pin it if you cannot migrate yet.

## What changed

| Area | v3 | v4 |
|---|---|---|
| Classes | `.ftl-btn`, `.ftl-card`, `.ftl-app` … | `.btn`, `.card`, `.app` … (213 names) |
| Custom properties | `--ftl-text`, `--ftl-btn-bg` … | `--text`, `--btn-bg` … (503 names) |
| Keyframes | `ftl-spin`, `ftl-lamp-pulse`, `ftl-aqua-pulse` | `spinner-rotate`, `lamp-pulse`, `aqua-pulse` |
| Ids / storage keys (example pages) | `ftl-theme-link`, `ftl-theme-picker`, `ftl-example-theme` | `theme-link`, `theme-picker`, `example-theme` |
| Source/bundle files | `core/ftl-core.css`, `dist/ftl-core.css` … | `core/core.css`, `dist/core.css` … |
| JS | `window.ftlApplyIconTheme`, `data-ftl-drag` | `window.applyIconTheme`, `data-drag` |
| Cascade | bundles were unlayered | every bundle is wrapped in `@layer ui { … }` |
| Manifest | `version` was `ftl-<hash>`; no contract field | `version` is the bare hash; every entry has `"contract": 4` |

The product/repo name `ftl-themes`, the `html[data-theme="…"]` / `data-variant` /
`data-accent` attributes, the `is-*` state classes and the theme slugs are
**unchanged**.

## Migrate your code

```sh
# from the root of YOUR app (templates, CSS, JS, docs):
git submodule update --remote third_party/ftl-themes   # or however you pin it
python3 third_party/ftl-themes/scripts/migrate-v4.py --dry-run  templates static
python3 third_party/ftl-themes/scripts/migrate-v4.py            templates static
python3 third_party/ftl-themes/scripts/migrate-v4.py --check    templates static   # exits 1 if any legacy name remains
```

The codemod uses the exact-name map in `scripts/v4-rename-map.json`, not a blind
regex, so an unrelated `ftl-…` string in your own code is left alone unless it is
a name v3 shipped. It cannot see class names built at runtime (`"ftl-" + kind`);
`--check` flags those, and a `git grep -n "ftl-"` afterwards is a sensible last step.
Update any `<link>` to `dist/ftl-core.css` → `dist/core.css`.

## Read this before you upgrade: name collisions

Dropping the prefix removes the collision protection it gave you. The bundles are
therefore wrapped in `@layer ui`, so **your unlayered CSS always beats the library**.
That fixes your app overriding v4, but it also means an *unlayered* framework
stylesheet will now beat v4 wherever both define the same class.

- **Bootstrap 5** — these v4 class names are identical to Bootstrap's and will
  collide if both are loaded: `.accordion-item, .alert, .badge, .btn, .btn-close, .btn-danger, .btn-primary, .btn-secondary, .btn-sm, .btn-success, .card, .carousel, .container, .dropdown, .dropdown-item, .input-group, .modal, .modal-footer, .modal-header, .modal-lg, .modal-sm, .modal-xl, .nav, .nav-item, .pagination, .popover, .progress, .ratio, .row, .spinner, .stack, .table, .text-muted, .toast, .visually-hidden`.
  Put Bootstrap in a lower layer than the library:
  `@layer bootstrap, ui, app; @import url("bootstrap.css") layer(bootstrap);`.
  Bootstrap's `.btn-group`/`.btn-toolbar` are not the same thing as ftl-themes'.
- **Tailwind** — `.container`, `.divide-y`, `.flex`, `.grid`, `.table` share names with Tailwind utilities but
  mean something different (for example `.flex` here also sets a gap, and `.grid` is
  an auto-fit grid, not `display: grid`). Do not load both without a layer order.
- **Custom properties are now bare** (`--text`, `--bg`, `--border`, `--accent`, …).
  Any app that already defines a property of the same name will fight the theme.
  Check `grep -rn -- '--text\|--bg\|--border\|--accent\|--radius\|--font' your/css`.
